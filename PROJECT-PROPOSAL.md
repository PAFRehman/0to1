## 2 Project Overview and Problem Statement

The problem: Students meet blockchain through theory but have few approachable ways to practise wallets, signatures and transaction verification. Ordinary portfolios also lack a shared, verifiable history of submitted work.

Proposed solution: We will build a guided web studio for minting media, notes and creative signatures on Base Sepolia. Students can prove a private file without uploading it, link project revisions and verify public records.

Target users: University students, classmates and instructors running introductory blockchain labs.

## 3 Core Objectives

- Provide an encrypted in-site wallet and external wallet connections with clear testnet gas review.
- Record signed creations, file checksums and revision links in an open ERC-721 smart contract.
- Build a live public wall, peer acknowledgements and a contract-backed learning passport.
## 4 Scope of Work

In scope: Wallet creation, backup and connection; local draft CRUD; media, note, signature and file-proof minting; proof verification; revision history; peer witnesses; shared classroom walls; one penguin guide, moving 3D scenery and music.

Out of scope: Mainnet payments, token trading, university-issued credentials, legal copyright certification and editing or deleting confirmed blockchain records.

## 5 Tech Stack and Tools

Frontend: Next.js, React, TypeScript, Three.js actors and native video scenery.

Backend and data: Next.js server routes; Base Sepolia contract state as the public record; IPFS via Pinata for larger media; encrypted browser storage for wallets and drafts.

APIs and tools: Solidity, OpenZeppelin, viem, EIP-1193/EIP-6963, optional WalletConnect, Anvil, Git/GitHub and Vercel.

## 6 High Level Methodology and SDLC

Development model: Agile with two-week iterations and student usability feedback.

Requirements → UI and contract design → implementation → contract, wallet and browser testing → deployment and evaluation. Assess first-mint completion, proof correctness and confirmation-to-gallery delay.

## 7 Work Plan and Timeline

- Weeks 1–3: Requirements, SRS, workflow design and contract data schema.
- Weeks 4–7: Contract, wallet encryption, server routes and IPFS integration.
- Weeks 8–11: Guided interface, public wall, revisions and learning passport.
- Weeks 12–14: Unit, contract, integration and mobile testing; student pilot and fixes.
- Weeks 15–16: Base Sepolia deployment, documentation and presentation preparation.
